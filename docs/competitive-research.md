# Prometheus × Codex / Claude Code / Cursor — 竞品调研与差距分析

调研日期：2026-10-17。三份独立调研分别覆盖 Codex（桌面/IDE/CLI/Cloud）、Claude Code（桌面/CLI/Web）、Cursor（IDE/Agents Window）。
本文件回答三个问题：他们做成什么样、我们现在有什么、下一步必须补什么。

---

## 一、三家已经收敛的共同范式

三家在 2025–2026 年独立演化出了几乎相同的骨架。这不是巧合，是这类产品的最优结构。

### 1. 三栏 + 可停靠面板

| | 左侧 | 中间 | 右侧 |
|---|---|---|---|
| Codex 桌面 | 图标栏 52px + 会话侧栏 224px | 对话列 | 产物/Review 面板 400px |
| Cursor Agents | 统一侧栏（Projects/Files/Changes/PRs/Terminals/Browsers） | 对话列（可调 600–1600px） | 标签式工作区（Files/Changes/PR/Browser/Terminal/Canvas） |
| Claude Desktop | 会话侧栏（Pinned/Routines/自定义分区） | 对话 | 可自由拖拽的面板网格（diff/browser/terminal/file/plan/tasks） |

共同点：**对话是主视图，但代码/review 是并排的第二工作区，不是弹窗**。Claude 和 Cursor 甚至允许面板拖出成独立窗口。

### 2. Diff 是第一公民

- 三家都有一条固定的审查闭环：**改动统计 → diff 视图 → 行内评论 → 反馈给 agent → 继续**。
- Claude：`+12 -1` 芯片 → 文件列表 + 逐行 diff → 行内评论批量发送 → Create PR → CI 状态条 → Auto-fix。
- Cursor：Changes 面板支持范围切换（未提交 / **最后一次 agent 回合** / 已暂存 / 分支全部），逐文件 Keep / Review Next。
- Codex：Review 面板覆盖全部 Git 状态（含用户自己的未提交改动），分阶段/未分阶段，逐行评论，可直接 stage/revert/commit/push。

### 3. 权限是可命名、可解释的模式

| 产品 | 模式 |
|---|---|
| Claude | Manual / Accept edits / Plan / Auto / Bypass |
| Codex | Request approval / Approve for me（自动审查子代理）/ Full access / Custom |
| Cursor | Auto-review：白名单直接执行、可沙箱化则沙箱执行、其余交分类器决定 |

共同点：**模式显示在输入框旁**，权限卡片显示具体命令/改动，并提供「允许一次 / 始终允许 / 转到自动模式」。

### 4. 任务是有状态的对象

Ready / Working / Needs input / Error 这套状态在 Codex 侧栏、Claude agent view、Cursor 子代理托盘里都存在，并配通知（桌面通知、菜单栏、甚至「宠物」）。

### 5. 检查点与回滚

Cursor 有自动检查点（可预览、可恢复文件）；Claude 有 `/rewind`（恢复对话和/或代码）；Codex 有 worktree + `codex apply`。**改坏了能退回去**是基本预期。

### 6. 会话可并行、可隔离

worktree per session（Claude/Cursor/Codex 都有）、子代理（三家都有）、后台 session、云端执行。侧栏列表按项目/状态分组，支持置顶、归档、搜索。

### 7. 扩展点统一

MCP、skills、hooks、plugins、rules（AGENTS.md / CLAUDE.md / PROMETHEUS.md）、memory。Codex 和 Claude 都强调**一份配置跨所有表面**。

### 8. 上下文与用量可视

- 输入框附近有上下文占比（百分比或环形图）。
- 有 `/usage`、`/context`、`/cost`。
- 三家的用户投诉里，「用量不透明」都是高频项——说明这很重要。

### 9. 输入的交织控制

- **排队 vs 插入 vs 打断**是一等公民（Cursor 明确三态，Claude 支持工作途中发消息、下一工具边界读取）。
- 斜杠命令、`@` 文件引用、`!` shell、图片粘贴。

### 10. 安静的视觉语言

- 系统字体 + 等宽代码字体；14px 基准。
- 细线分隔（1px hairline），少阴影；圆角 8–12px。
- 单一强调色；深色/浅色完整对等；尊重减少动效设置。
- 工具调用折叠成一行摘要，可展开看完整输出。

## 三、差距清单（按优先级）

### P0 — 没有它就不像同类产品

1. **Diff 审查视图**
   现在改完只显示「修改了 N 个文件」。必须有：文件列表 + 逐行 diff + 行内评论 + 一键把评论发给 agent。
   实现要点：host 在写文件前保存原内容快照，按会话累积变更集；新增 `changes` 面板；diff 渲染用行级 + 词级高亮。

2. **检查点与回滚**
   每个写/改操作前快照文件（内容或 git stash），提供「恢复到本轮之前 / 恢复到某检查点」。
   实现要点：`~/.prometheus/checkpoints/<session>/`；工具执行前记录；UI 时间线可点。

3. **文件树面板**
   现在只能靠模型 `list_files`。需要可浏览、可点击打开、可拖入上下文的树。
   实现要点：主进程读目录（限制在工作区），惰性展开，忽略 node_modules/.git。

4. **内嵌终端**
   bash 输出目前是只读文本。需要可交互终端标签页。
   实现要点：node-pty 或简单子进程 + xterm.js；或先做只读的「命令输出面板」作为过渡。

5. **设置页**
   所有配置靠手改 JSON 不合理。需要：服务端点、API key、模型白名单、默认模式、默认思考强度、自动批准规则、主题、语言、快捷键。
   实现要点：写入 `~/.prometheus/config.json`，通过 host 命令热更新。

6. **键盘快捷键面板**
   类似 Claude 的 `Cmd+/`、Cursor 的命令面板。至少：新建对话、切换模式、切换模型、切换思考强度、打开设置、打开 diff、聚焦输入、停止、折叠侧栏。

### P1 — 显著影响可用性

7. **Git 集成**
   分支显示、改动统计、暂存/提交、创建 PR（调用 `gh`）。至少先做「当前分支 + 未提交改动数」显示。
8. **会话搜索与分组**
   侧栏按项目分组、搜索、置顶、归档、重命名。
9. **通知**
   长任务完成/需要输入时发系统通知（Electron `Notification`）。
10. **排队 / 插入消息**
    运行中输入的消息可以排队，或在下一工具边界插入。
11. **`@` 文件引用**
    输入框里 `@` 触发文件补全，选中后把文件内容或路径带入上下文。
12. **对话内搜索与跳转**
    `Cmd+F` 在对话里查找；点击工具行跳转到对应文件/行。
13. **任务状态模型**
    会话有 Ready/Working/Needs input/Error 状态，侧栏可见，与通知联动。
14. **初始引导**
    首次启动：选工作区 → 配置端点/key → 示例提示。

### P2 — 深度与差异化

15. **MCP 支持**
    stdio/HTTP MCP 客户端，工具动态注入。
16. **Skills / 自定义命令**
    `.prometheus/commands/*.md` 作为斜杠命令；skills 目录。
17. **Hooks**
    工具调用前后、会话开始/结束的事件钩子。
18. **Worktree 隔离**
    每个会话可开在独立 git worktree。
19. **多会话并行**
    侧栏切换时多个 agent 同时跑。
20. **子代理可视化**
    子代理作为可展开的嵌套视图，而不是一行日志。
21. **浏览器面板**
    内置 webview + 让 agent 读取页面/截图。
22. **画布/产物**
    agent 生成的 HTML/图表在侧栏预览。
23. **语音输入**
24. **Code review 模式**
    `/review`：对当前改动做系统化审查并给出按严重度排序的发现。

### P3 — 打磨

25. 工具调用密度（紧凑/平衡/详细）
26. 消息时间线与「最后一次 agent 回合」diff 范围
27. 会话导出（markdown）
28. 多工作区（同一窗口多个项目）
29. 自动更新
30. 崩溃恢复

## 五、建议的执行顺序

**第一阶段：让它「像个工具」（P0）**
diff 视图 → 检查点 → 文件树 → 设置页 → 快捷键面板 → 修打包 bug。

**第二阶段：让它「顺手」（P1）**
Git 状态与提交 → 会话分组搜索 → 通知 → 排队消息 → `@` 引用 → 任务状态。

**第三阶段：让它「能扩展」（P2）**
MCP → skills/commands → hooks → worktree → 多会话并行。

**第四阶段：差异化（P3）**
浏览器面板、画布、语音、code review 模式。

每阶段结束都应：跑测试、真实模型验证、截图确认、提交。
